# Настройка SSH и анализ сетевого трафика в GNS3 и Wireshark

## 📌 Описание проекта

Учебная лабораторная работа по настройке безопасного удалённого доступа к сетевому оборудованию Cisco и анализу сетевого трафика.

В проекте используются два виртуальных маршрутизатора Cisco IOS в GNS3 и Wireshark для захвата и анализа пакетов.

Основное внимание уделяется настройке SSH, проверке доступности TCP-порта 22 и изучению TCP-соединения.

## 🎯 Цели работы

* Настроить SSH версии 2 на маршрутизаторе Cisco IOS.
* Создать локального пользователя для аутентификации.
* Сгенерировать RSA-ключи.
* Настроить VTY-линии для удалённого доступа.
* Проверить доступность TCP-порта 22.
* Установить SSH-соединение между маршрутизаторами.
* Захватить сетевой трафик с помощью Wireshark.
* Изучить TCP handshake и основные TCP-флаги.

## 🛠️ Используемые инструменты и технологии

* GNS3 — моделирование сетевой инфраструктуры.
* Cisco IOS — настройка маршрутизаторов.
* Wireshark — захват и анализ сетевых пакетов.
* SSH — безопасное удалённое управление.
* TCP/IP — сетевые протоколы.
* Telnet-клиент — проверка доступности TCP-порта.

## 🌐 Топология сети

В лабораторной работе используются два маршрутизатора Cisco, соединённых Ethernet-каналом.

| Устройство | Интерфейс       | IP-адрес         |
| ---------- | --------------- | ---------------- |
| R1         | FastEthernet0/0 | `192.168.1.1/24` |
| R2         | FastEthernet0/0 | `192.168.1.2/24` |

**Роли устройств:**

* **R1** — SSH-сервер.
* **R2** — SSH-клиент и источник тестового трафика.

## ⚙️ Ход выполнения работы

### 1. Настройка SSH на R1

Настройка доменного имени:

```text
ip domain name example.com
```

Создание локального пользователя:

```text
username admin privilege 15 secret <ПАРОЛЬ>
```

Генерация RSA-ключей:

```text
crypto key generate rsa
```

Включение SSH версии 2:

```text
ip ssh version 2
```

Настройка VTY-линий:

```text
line vty 0 4
 login local
 transport input telnet ssh
```

Команда `login local` включает проверку учётных данных по локальной базе пользователей. Команда `transport input telnet ssh` разрешает входящие подключения по Telnet и SSH.

**Примечание по безопасности:** Telnet оставлен доступным в рамках учебной лабораторной работы. В реальной инфраструктуре рекомендуется использовать SSH и ограничивать доступ к управлению сетевым оборудованием.

### 2. Проверка IP-связности

На маршрутизаторе R2 выполнена команда:

```text
ping 192.168.1.1
```

Цель — проверить доступность R1 по IP-сети.

### 3. Проверка доступности TCP-порта 22

На R2 выполнена команда:

```text
telnet 192.168.1.1 22
```

В ответ получена строка идентификации SSH-сервера:

```text
Open
SSH-2.0-Cisco-1.25
```

Это подтверждает, что TCP-соединение с портом 22 устанавливается и SSH-сервис отвечает.

Telnet-клиент в данном случае используется только для проверки TCP-порта. Это не означает, что на порту 22 работает протокол Telnet.

### 4. Подключение по SSH

На R2 выполнена команда:

```text
ssh -l admin 192.168.1.1
```

После ввода корректного пароля успешно выполнен вход в CLI маршрутизатора R1.

Для завершения удалённого сеанса использована команда:

```text
exit
```

### 5. Захват и анализ трафика в Wireshark

В GNS3 запущен захват трафика на соединении между R1 и R2.

Для отображения пакетов, связанных с TCP-портом 22, использован фильтр Wireshark:

```text
tcp.port == 22
```

В ходе анализа изучаются:

* IP-адреса источника и назначения.
* TCP-порты источника и назначения.
* TCP-флаги.
* Номера последовательности и подтверждения.
* Размеры пакетов и время передачи.
* Процесс установления TCP-соединения.

### 6. Анализ TCP handshake

Установка TCP-соединения выполняется в три этапа:

1. **SYN** — R2 инициирует соединение с R1.
2. **SYN-ACK** — R1 подтверждает запрос и отправляет ответ.
3. **ACK** — R2 подтверждает ответ R1.

После завершения трёхстороннего рукопожатия TCP-соединение установлено и может использоваться для обмена данными SSH.
